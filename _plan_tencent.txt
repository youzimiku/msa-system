二、完整会议纪要（业务逻辑梳理）
按业务主题组织，覆盖 9 场会议的全部定稿结论；待确认事项集中在第五部分单列。
2.1 总体业务链路
基础数据维护→
MSA 计划创建（选器具组/选特性/勾方法）→
生成分析台账（每方法一行）→
选择样本 + 选择操作人员→
样本录入（二维矩阵）→
手动分析（调丁宁程序）→
查看结果 / 审核确认
关键定位（9/15 15:02 张会娟）：一个 MSA 计划 → 多个台账（每个分析方法一行）；抽样规则（人数/次数/样本数）下沉到台账层，计划层不指定；"一个计划只能对一个量具，一个检验项目可适用多个量具组"。

复用现有台账、不重建，新增字段：周期值(int) / 周期单位 / MSA标识 / 区域组（9/15 10:00）。
器具组和器具明细两层都加 MSA 履历字段：MSA状态（代码表2位）、MSA执行时间（14位）、上次执行时间、分析人员（32位）（9/15 10:00）。
器具组表不存成员器具ID/器具编号（一对多无法记，走关联查询）；去掉岗位编码字段，直接关联岗位表（9/15 10:00）。
周期单位优先按月；若有不满一个月的周期，再加单位选择（9/15 10:00，仍属待确认）。
全库 MSA 相关表前缀统一 qmsa_；备注字段排到表结构末尾、时间类字段集中排序（9/15 10:00）。
MSA 履历（记录表）结构：计划号（20位）+ 操作时间 + 分析人 + 结论 + 操作人（操作人与分析人区分开：分析人=执行分析的人，操作人=操作录入的人），编号用"管理号"（9/15 10:00）。
该页面当前在原型中已隐藏（你的决定），表结构调整不影响页面展示。

抽样规则（人数/次数/样本数）从计划层移除，下沉到台账层（9/15 15:02）。
计划表固定加 7 个分析方法结论字段平铺（界面好横向展示），每个方法一个状态；再加一个总状态（9/15 15:02）。
状态 5 种：不做 / 生成(未做) / OK / NG / 有条件接受，两个状态代码位足够（9/15 15:02 张会娟原话："5 个状态嘛，两个代码够了"）。
创建计划交互（9/15 15:02 + 15:44）：选被测参数 → 自动列出该参数下可做的分析方法（多选勾选）→ 点确定 → 按勾选在下方生成台账行（DataView/DSO，每行填人数/次数/样本数，逐行保存）→ 确认创建 后真正落库。
9/16 09:21 定稿：维持"按器具组生成计划"底层逻辑。
计划类型（人员/设备）是否保留：石佳阳在群里说不要了，但客户要的，需与业务确认（9/15 15:02）。
分辨力处置（9/16 09:21 定稿）：判定为"< 公差1/10 且 NDC≥5"，由丁宁程序输出 NDC 参数，系统在每个器具 MSA 计划结论判定时自动写入（人员计划不需要分辨力），不单独生成计划。
2.8 五个台账页面（统一为 MSA 分析台账）
废弃 GRR/Kappa 分表，新建统一 MSA 分析台账表，用"台账类型 / 分析类型"字段区分（GRR、KAPPA、线性、偏移、稳定性、Cg/Cgk…）（9/15 15:44 张会娟："表肯定是要新建的…就叫 MSA 的分析台账"）。
台账表加 MSA计划号（非主键，18位，与计划编号保持一致）（9/15 15:44）。
组合分析（线性+偏移、重复性+再现性共用一套样本）：加分析组 + 序号；状态1/状态2、结论1/结论2（9/15 15:44）。
分析类型需包含组合类型："线性/偏移"要与单独的线性、单独的偏移区分开（9/15 15:44）；"偏倚"用倚不是移动的"移"（元工原话）。
台账冗余字段（方便写接口）：被测项目、量具编号、量具名称（冗余）、零件号 + 零件名（两个独立字段）、工序号 + 工序名（两个独立字段）、部门、标准值 / 规格上限 / 规格下限、测量次数 / 测量人数 / 样本数、公差值（9/15 15:44 / 16:23）。
删字段：执行状态（与状态重复）、角色标识、用户名、"分厂车间"改为车间、所有带 P 的错误字段（生成时识别错的）（9/15 17:03）。
审核：统一审核状态；新增审核发起人 / 审核确认人 / 审核发起时间 / 审核确认时间（审核发起人=分派确认人的人；确认人=确认的人）（9/15 17:03）。
实测值次序字段去掉（时阳阳解释：是崔英杰多写的字段，样本号已能唯一标识）（9/15 16:23）。
样本录入界面：增加"选择样本"功能（从样本库挑，待办项）；"选择人"排序太靠后要拿出来（9/15 16:23）。
台账行按钮精简为 4 个：样本/人员选择（合并）· 查看结果 · 审核 · 分析（"手动分析"就叫"分析"）（9/15 16:23）。
2.9 样本录入页面
选择样本 + 选择人员合并到同一弹窗：先勾样本（从样本库）→ 再勾人员 → 点确定生成样本记录（9/15 15:44 / 16:23）。
采样计划号 SamplingPlanNum 是样本 ↔ 台账的核心关联：一个采样计划号 → 一套样本 → 多个台账计划；生成逻辑在创建分析方法（台账）时自动生成，需考虑合并逻辑（同一套样本合并到同一采样计划号）（9/15 15:44）。
数据结构：交叉型 = 样本数 × 人数条记录；嵌套型 = 样本数条记录（9/15 16:23 张会娟原话："我三个样本，两个人是 6 条数据"）。
样本是否已生成判定：台账表记样本编号，有就不生成；组合分析共享同一套样本编号（9/15 16:23）。
录入完成时同步更新关联计划/台账状态（9/15 15:44）。
不可编辑字段统一用 Label 纯文字展示（无边框），不做 disabled 控件（9/15 16:23）。
