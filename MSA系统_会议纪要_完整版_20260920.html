第一场：14:17–15:17 质量管理系统功能评审与交互优化研讨会

基本信息

主题质量管理系统功能评审与交互优化研讨会

参会人张会娟、张韫仪、高国翔、元工_刘科壮

时长约 60 分钟

一、检验标准与器具组绑定

  • 检验标准列表改为弹窗化展示（从主页面下移到被测参数列表的"检验标准"按钮触发弹窗）。
  • 器具组与检验标准为一对一绑定关系（万小云确认，非一对多）。
  • 检验标准号自动生成。
  • 批量绑定检验标准功能暂不做，高国翔跟万小云确认用户倾向后再定。

二、JR（计量型研究）与分辨率自动绑定

  • JR 选中时后台自动写入分辨率数据；前台不自动勾选，前台使用 checkbox 样式（不是右侧打勾）。
  • JR 和分辨率绑定：前台用户必须手动勾选两个，但后台只要选了 JR 就自动把分辨率写上去。

三、判定结论分级

  • 判定结论分四级：非常理想 / 理想 / 可接受 / 不接受(NG)，结论为下拉单选。
  • 前三个等级均属"可接受"等级，第四个为 NG。
  • GRR 有"有条件接受"状态。

四、抽样规则加工厂车间维度

  • 抽样规则需增加工厂、车间维度（同一方法不同车间差异化配置）。
  • 方法和工厂车间是一对多关系，主表要加工厂车间字段。
  • 方法名称显示，方法代码不显示。

五、计算参数维护

  • 参数编号和参数名称系统固定，不可编辑（只有超级管理员可改）。
  • 用户只能改参数值和默认值。
  • 参数编号不自动生成，需手填（如 α、P、CGK 等固定代码）。

六、被测参数版本管理

  • 点"升版"复制当前行，版本号 +1，状态自动启用，旧版本自动停用。
  • 同一参数编号只能有一个启用版本。
  • 列表默认查询启用状态的数据。
  • 升版后若有未完成计划/台账引用旧版，需强制提醒用户是否同步升版，已完成的计划/台账不动。
  • 此提醒逻辑高国翔找万小云确认。

七、样本库

  • 被测参数与特殊特性一对一（张会娟让高国翔跟石阳确认是否一对一）。
  • 样本库要带出来特殊特性字段。
  • 样本库本身不需要版本管理。
  • 样本库要加创建人/创建时间字段。

八、判断规则表达式

  • 是用整体表达式（支持 and/or、括号）还是拆成单条件，待定让刘科壮考虑。
  • 判定条件参考石阳发群里的"五项分类"文件（黄色文件），按那个走。
  • 判断规则页签和计算参数页签位置互换（先计算参数后判断规则）。

九、判断规则页签展示

  • 方法/工厂/车间不在列表里显示，放在页签上面用 label 纯文本显示。

十、表日志触发器

  • 新值和旧值都为空不记录，只有不为空且不一致才记录。

第二场：14:57–15:57 质量管理系统Kappa分析模块评审与优化研讨会

基本信息

主题质量管理系统Kappa分析模块评审与优化研讨会

参会人张会娟、高国翔、张韫仪、元工_刘科壮

时长约 60 分钟

一、Kappa样件判定逻辑与标准值维护

  • Kappa样件的"判定状态"（合格/不合格）直接维护在"标准值"字段中，以 0 和 1 的数值形式存储，用于 Kappa 分析计算。
  • "判定状态"与"标准值"在 Kappa 场景下去重，统一使用标准值控制逻辑。
  • 判定状态填到标准值字段，不是真值字段。

二、样件编码补打

  • 支持补打二维码，打印样式需包含零件名称及编号（不只打二维码）。
  • 纸张规格 2×6 / 3×6 / 9×6 待确认（看客户打印机条码规格）。
  • 是否支持多选批量打印待确认。
  • 导入导出和打印模板自己定，不找外部。

三、表日志优化

  • 新值和旧值都为空不记，都不空且不一致才记。

四、样本库列表显示创建人/创建时间

  • 样本库列表要显示创建人/创建时间字段。

五、计划创建交互优化

  • 分析方法"确定"按钮改叫"增加"（只负责添加行，不负责删除），删除走行按钮。
  • 新增时用 DSO（不是 DataView），点增加先结束编辑保存、再刷新 DSO 打开新行。
  • 版本默认带出当前启用最新版本，同一参数仅一个启用版本。

六、计划创建后字段编辑限制

  • 计划创建后，除"责任人"外其他字段（零件号、测量参数等）都不可修改，页面禁用。

七、详情抽屉分组展示

  • 去掉背景色、边框、标签样式，纯文字展示。
  • 字段分三组：基本信息（含测量参数/人员/责任人）、抽样规则、执行状态。
  • 字段名不要冒号，字段值左对齐，字段名和值同一行。
  • 去掉"（取样计划→录入→分析→结论归集）"和"共 N 个分计划，任一不合格则总计划不合格"这两段文字。
  • 分计划列表标题和上面分组对齐，去掉小蓝条。

八、详情抽屉加"台账查看"按钮

  • 详情页加"台账查看"按钮直接跳台账独立页面，不要内嵌复杂操作。

九、权限模型

  • 分两种录入权限："仅录个人"（默认，只能看自己录入的数据）和"可录全部"（管理员权限，能看所有台账）。
  • 不按责任人字段走，按账号权限配置。
  • 所有页面按钮都要做权限控制。

十、人员选择校验

  • 人员选择弹窗显示已选人数和要求人数对比（如要求 3 人选了几人）。
  • 提交时二次校验多选少选。

十一、样本号录入方式

  • 样本号不在计划创建阶段预定义，在数据录入阶段扫描或手动输入。

十二、台账列表三字段显示规则

  • GRR/KAPPA：只显示人员字段。
  • 线性/偏倚：显示样本和人员字段。
  • Cg/Cgk：显示人员和样本字段。
  • 稳定性：显示人员和工位（单选各一个）。

第三场：15:37–16:37 MSA系统功能逻辑与界面交互评审

基本信息

主题MSA系统功能逻辑与界面交互评审

参会人张会娟、yy（杨姐）、高国翔、张韫仪、元工_刘科壮

时长约 60 分钟

一、样本选择逻辑统一

  • 生产件（GRR、Kappa）不选样本，样本号在录入阶段扫描。
  • 标准件（线性、偏倚性）必须在计划阶段提前选好样本。
  • yy（杨姐）确认：凡是生产件都不选样本，凡是标准件都要提前把样本选好。
  • GRR/Kappa 录入时要求盲测乱序、随机，所以不预定义样本号。

二、人员选择交互优化

  • 人员选择弹窗增加部门和岗位筛选条件，避免人员列表过长。

三、工位取值来源

  • 工位数据来源于 Work Post 表（不是 Work Center 表）。
  • 若计划中未填写工厂和车间，则拉取全部产线；若已填写，则仅拉取对应工厂和车间下的产线。
  • 工位选择只需要"产线"一个筛选条件。
  • Work Center 是工序表，Work Post 是工位表，刘科壮去跟周明鹏确认到底用哪个。

四、样本库与特殊特性

  • 样本库选择被测参数后，不需要再带出特殊特性字段（yy 确认）。
  • 样本库有样本编号直接关联被测参数就够了。

五、样本状态字段

  • 原"判定状态"字段改名为"样本状态"。
  • 下拉值：合格/不合格，以及 1/2/3/4/5 等级序列。
  • 不同零件等级序列不同（有的零件用 0/1，有的用 1/2/3/4/5），由代码表维护。
  • 下拉框列出所有可能值，由用户自己选。

六、被测参数升版与历史计划处理

  • 新版本发布后旧版本自动作废，但新版本需手动启用（不是自动启用）。
  • 新版本启用后，旧版本自动停用。
  • 已生成的旧版计划不受影响，继续按旧版执行。
  • 新版本启用时，若有未完成的旧版计划，系统只做提示，不强制更新。
  • 提示语："被测参数升版后，已创建的 MSA 计划仍关联旧版本参数；如需使用新版本，请重新创建计划。"
  • 已完成的计划/台账不动。

七、Kappa交叉分析表取消

  • Minitab 算法（基于 Pi 平均值）与 Excel 简易算法（Po/Pe）存在差异。
  • 用户实际测量次数通常大于 3 次，Po/Pe 算法不适用。
  • 决定取消 Kappa 交叉分析表展示，最终报告只保留 Minitab 计算结果。
  • 删除交叉表及 Po/Pe 相关字段。

八、GRR字段位置修正

  • "默认GRR结构"和"计算方法"字段不应加在"检验标准"表，应加在"分析方法"表（方法层）。
  • 删除冗余的"默认结构"和"是否强制交叉"字段。
  • "GRR方法"字段改名为"计算方法"，值为：均值极差法 / 方差分析法。
  • "默认GRR结构"值为：交叉CROSSED / 嵌套NESTED / 扩展EXPANDED。
  • 这两个字段是单选下拉框。

九、列表操作按钮数量控制

  • 列表页操作按钮控制在 2–3 个以内。
  • 取消"更多"折叠菜单设计，常用功能按钮直接外露，低频操作移至页面顶部。
  • 高国翔向周明鹏确认用户电脑分辨率及按钮数量规范。

第四场：16:18–17:18 质量检测系统交互优化与数据规范研讨会

基本信息

主题质量检测系统交互优化与数据规范研讨会

参会人张会娟、高国翔、yy（杨姐）、元工_刘科壮

时长约 60 分钟

一、台账确认交互重构

  • 废弃行内下拉框操作方式，确认操作统一移至页面顶部。
  • 通过弹窗进行"同意"或"驳回"操作。
  • 状态流转：确认即代表计划闭环；驳回需填写驳回原因，支持二次发起确认。
  • 状态值：确认 / 驳回（不是未确认/已确认）。
  • 被驳回的和未确认的都可以再次发起确认。

二、GRR/Kappa数据录入界面

  • 采用交叉表（DSO）样式：左侧样本号，上方操作员（A/B/C），中间测量值。
  • 支持合并单元格（同一样本多人测量时样本号合并显示）。
  • 人员选择在页面顶部下拉框，不在行内。
  • 默认选中当前登录人，管理员可见全部人员（全部/A/B...）。
  • 普通操作员登录时，DSO where 条件自动过滤，只显示该操作员的数据行。
  • 一进界面就默认闪编（编辑）状态，关闭界面自动提交。

三、盲测与数据排序

  • GRR 分析需遵循盲测和随机性原则，录入时数据顺序是打乱的。
  • 提交至后端模型前，必须按照样本编号（Sample ID）重新排序。
  • 排序后按操作员+样本编号顺序提供给丁宁（算法端），确保控制图绘制正确。
  • 刘科壮已按样本ID+操作员ID排序。

四、线性/偏倚录入

  • 在线性分析中，除标准件、实测值外，必须增加"偏移"字段。
  • 字段顺序：样本号、测量值、偏移。
  • 线性/偏倚在样本选择时同时绑定操作员（选样本时加人员选择）。
  • 偏移分析是同一个操作员，线性不一定（5 件按不同量程）。
  • 偏移和实测值是分开录的（不是合并成一列）。

五、稳定性分析简化

  • 稳定性（SPC）仅需录入子组号、样本号、样本值三个核心字段。
  • 剔除产线、机台、供应商、客户等冗余信息。
  • 子组号即测量次数（第1次、第2次...）。
  • 控制图号等字段自动生成，不需用户录入。

六、各录入页面字段汇总

分析类型录入字段
GRR样本号（合并单元格）、人员（A/B/C）、测1/测2/测3、录入人、录入时间
Kappa样本号、人员、测1/测2/测3（同GRR交叉表样式）
线性/偏倚样本号、测量值、偏移、录入人、录入时间
稳定性子组号、样本号、样本值
Cg/Cgk样本号、人员、测量值（类似GRR但单人）

七、录入时间字段

  • 所有数据录入页面都要有录入时间字段，默认当前时间。
  • 录入时间跟在每一行数据上，不显示在顶部。
  • 未录入数据时录入时间为空。
