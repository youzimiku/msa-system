2.1 报告算法规则（本场最核心、颗粒度最细的部分）
CG&CGK（测量能力指数）
固定阈值：1.33 / 5% / 15%（CGK>1.33、EV≤5%、偏倚≤15% 为合格）；30% 阈值不用（丁宁："第二个有15%和30%，现在只用15，30不用"）。
阈值作为固定参数传入计算逻辑，业务基本不调，仅上游行业标准变更时才调整（万小云："基本不会调…除非上游行业标准变更"）。
报告中的"标准 T 值 / 标准判定值"等右侧列 = 用标准阈值（1.33/5%/15%）代入算出的标准值；左侧为实际值，实际值落在标准范围内即合格（张会娟："左边 14.87% 是实际值，实际值<标准值→合格"）。
报告参照 Minitab 的 CG&CGK 报告格式，只保留核心结果字段：参考值 / 均值 / 标准差 / 6σ / 公差 / 偏移 / T 值 / P 值 / CG / CGK / 变异的重复性 / 变异的重复偏倚；剔除中间计算过程字段（如"加两倍SG""加0.1倍容差"等出图过程数据不展示）。
输出比 Minitab 多的字段：N（有效数，总数不再单显）、AC。
单位与检测类型匹配：硬度类自动匹配 HV 单位；移除清洁度模板误带的"拉伸长度 / 拉伸角度 / 拉伸强度"等无关标签（万小云指出模板问题）。
报告要有表头（分析对象、器具组、人员、时间）。
Kappa（计数型一致性）
只保留：检验员自身一致性、检验员与标准一致性、检验员之间一致性 + 对应 Kappa 统计量；剔除 Z 值、P 值、Cohen Kappa、标准物 Z 值。
新增三个核心指标：漏判率、误判率、有效性（有效性 = 匹配数 ÷ 总数，如 48/50 = 96%）。
"评估一致性"名称改为与 SOP 一致的写法（万小云："评估一致性这个名称要改一下，SOP 上是通用的写法…对应不上比较麻烦"）。
移除"交叉不一致汇总表"（评估与标准不一致的汇总表不要，没人看）。
只输出两个核心结论图：检验员自身一致性 + 检验员与标准一致性。
多组 Kappa 取最小值作最终判定依据（时阳阳提出，待用动态表验证）。
1–3 名检验员为常规场景，按默认规则输出，无需额外配置。
报告展示：绿色区域（结论）显示、黄色区域（中间计算数据）不显示（万小云："绿色这一块要显示…黄色这一块作为中间计算数据，可以不显示"）。
GR&R（量具重复性和再现性）
已开发完成、符合业务要求，无需调整；仅需补充最终合格判定结论（现有输出只有数据、没有最终合格/不合格结论）。
线性 / 偏倚
仅选线性 → 线性报告；仅选偏倚 → 偏倚报告；双选 → 默认合并取样，并走线性分析的抽样规则（时阳阳："线性和偏倚合在一起的话，就走线性那个规则"）。
两套规则：合并 = 5 件 × 测 10–12 次 ≈ 60 条记录；单独偏倚 = 标准件 15 个样本（15 个标准件各测若干次）。
一个台账出两个报告（线性一个、偏倚一个）。
线性判定规则：5 个点即使个别偏差超限，若整体偏差成比例也视为合格（时阳阳："专门找了一个算法…到时候再验证"——待验证）。
单独偏倚 = 单样本 t 检验 + 直方图。
现有输出已符合：常量、斜率、P 值、各量程偏移（5 段量程偏移）。
稳定性
采用均值-极差控制图（Xbar-R）；均值-标准差（Xbar-S）需子组≥8 个数据才适用，算法两者都支持，由用户在方法/分析时选择。
判定规则：同时满足「不超控制限」+「不超规格限」才合格（避免试产期控制限宽于规格限造成误判；超规格限直接判不合格）。
只输出：均值图 + 极差图 + 最终合格结论；不显示中间常数、不计算 CPK/PPK 等衍生指标；图内数值以图片形式出报告。
判定总原则（从严）
当前所有判定走"从严"：超 10% 即判不合格，不设 10–20% 可接受区间（万小云："我们实际都把它判成不合格…从严的判断"）。
关键件 / 普通件差异化判定：时阳阳提出"关键件>10% 直接不合格"，张会娟提出"如针对某产品某特性有专属判异规则，在被测参数维度单独维护"——本次先不加，后续在被测参数维度单独维护（🔶）。
2.2 基础数据维护
器具组组类型 = 器具组 + 各岗位组（新增"岗位组"类型：IQC检验组 / IPQC巡检组 / FQC终检组 / 动总GPR 等）；人员组直接对应岗位维度，组码 = 岗位码、不做自动映射（维护时手动选择岗位，保证灵活；讨论过"组码与岗位码设成一样、把组当岗位用"，最终定手动选择匹配）。
数据维护默认行内编辑：新增也在列表加空白行直接编辑，不做弹窗（万小云："就刚刚第一种吧"倾向行内编辑；时阳阳："与朱经理/周明鹏确认 UI 规范，没有统一要求就按行内编辑"）。
范围字段（样品数/人数/次数）：存储拆为上限、下限两个独立字段，页面显示仍为"范围"，编辑态拆两个控件；用于数据录入校验（防止未达样品范围导致分析出错）。
抽样方法模块新增计算参数页签（1.33 等判定参数在此维护）；固定判定参数暂不开放自定义（万小云："这些基本都固定，不会调"；时阳阳："哪些能调哪些不能调，会给出说明"）。
2.3 MSA 计划
新增按人员创建 MSA 计划：选人员组 → 默认生成 Kappa 台账，无需选方法、方法默认 KAPPA（"按人员创建的方法就是 KAPPA，默认就是 KAPPA，不用选"）。
计划状态三级（张会娟原话："打勾代表我要做，然后绿色代表我 OK，做了且 OK。红色代表是做了不 OK""勾的时候没有颜色，是灰色的那个勾"）：
✓灰色勾 = 计划已生成、该分析方法要做但还没出结论（未做）；
✓绿色勾 = 做了且 OK（合格）；
✕红色叉 = 做了不 OK（不合格）。
计划状态列旁加"详情"：点开直接看该维度对应台账数据（或跳转台账查看结果），方便导出给客户看（万小云："我一导出来，别人一看，好，这个合格，然后数据是多少"）。
创建计划新增责任人（必填）：三个必填 = 被测参数、分析人、责任人（张会娟："要加，那就要加个字段，要加个责任人"）。
质检区划改为"车间"（时阳阳："质检区划这边不用，这边只用车间…这个是用于多工厂才用，他们这边没有多工厂"）；车间非必填（质量部不需要车间）。
分辨率属于器具（在器具台账 / 器具组下，不是人员组），创建计划时由器具带出。
创建计划后，根据勾选的分析方法自动生成对应子台账（"选了方法之后，创建完毕之后，它都会产生下面那个子台账"）。
2.4 五个台账
字段调整：去掉"标准"字段，新增 分辨率、规格上限、规格下限、标准值、产品型号、工序 6 个字段（张会娟："分辨率，上下限，标准值…4 个字段…如果有型号的话，你应该把型号也加上…产品型号…还少了一个工序"）。
顶部全局导入按钮（导入不勾选、按文件内编号对系统编号）；导出支持多选勾选（张会娟："导出的时候我可能导第一行、第三行和第五行，这才需要勾选；导入不需要勾选，直接上面放一个导入按钮"）。
导入模板统一字段格式；Excel 批量导入后先预览确认再提交；导入完成后通过预览进入录入数据页面查看内容。
复制粘贴功能待与研发确认（新平台升级后是否支持 Excel 复制粘贴，张会娟："这个复制粘贴功能的话，可能要跟研发去确认一下"）。🔶
2.5 审核流程
台账顶部全局"审核""确认"两个按钮（方便多选批量，张会娟："就放在上面，这是方便你多选的嘛，你要放在行上，你就得一个一个做了"）。
审核弹人员选择框，选发给谁；默认按分析人所属部门匹配审核人（IQC 段发 IQC、IPQC 段发 IPQC，不必跨部门选）。
流程 = 发起（分析人/系统管理员）→ 审核（科室负责人）→ 确认（接收人）；一个计划一个发起 + 一个确认，不做多部门多人批量。
不合格的报告不审核（万小云："不合格的不审"）。
审核结束确认后，MSA 结果反馈到计量器具台账，不合格则推送。
走系统内简单按钮，不走复杂工作流（会议倾向"飞书，走飞书吧"，后简化为系统内两按钮）。
2.6 权限（三档）
台账默认只显示当前登录分析人的数据（顶部有"分析人"过滤条件，默认本人）；配"查看全部"权限（超级管理员）可看全部。
操作人只允许进入录入数据页面，无台账列表权限（看不到测量对象/标准等）；分析人字段位置前置。

4.4 冲突项（需你拍板）
冲突 #1（最重要）：计划状态体系三方不一致 ——
9/14 业务会说：3 种状态。张会娟原话："打勾代表我要做，绿色代表我 OK，红色代表是做了不 OK""勾的时候没有颜色，是灰色的那个勾"。即：灰勾=要做未做 / 绿勾=OK / 红叉=NG。
9/15 腾讯会说：5 种状态。张会娟原话："5 个状态嘛，两个代码够了"：不做 / 生成(未做) / OK / NG / 有条件接受。
你现行原型：4 种状态标识（绿勾=通过 / 红叉=不通过 / 灰横线=未做 / 圆点=不做，"有条件接受"算通过）。
分析：9/14 场更晚（当天下午）且是业务直接对齐，倾向以"灰勾/绿勾/红叉"三态为准；但 9/15 场又出现"有条件接受"独立状态。两者都存在"未做"表示法差异（灰勾 vs 灰横线）。建议：以 9/14 三态为骨架（灰勾=未做、绿=OK、红=NG），把"不做"与"有条件接受"是否保留、以及灰勾还是灰横线，一次问清张会娟。
冲突 #2：判定从严 vs "有条件接受"独立状态 —— 9/14 明确"超 10% 直接判不合格、不设 10–20% 可接受区间"，若按此执行，"有条件接受"状态在业务上不会出现；9/15 却把它列为第 5 态。需确认是保留状态位（算法暂不产生）还是直接去掉。
冲突 #3（口径差异，非硬冲突）：台账"分辨率" vs 你页面"分辨力" —— 9/14 通篇说"分辨率"（张会娟："分辨率，上下限，标准值…"），你此前已按全局规则把"分辨率"统一改"分辨力"（你记录项：所有页面分辨率改分辨力）。9/14 这场是口头用语，两者同一物，保持"分辨力"即可，但报告/表结构字段建议统一为一个词，避免口径混乱。
